# 网页时间线图分析恢复

第 7 步曾在任一图片异常时退出整批分析，已完成图片没有独立恢复结果；刷新后项目 JSON 中的 File 元信息也无法还原图片。所有图片共用一个服务端步骤标识，导致第一张成功后整批步骤已经被标为 succeeded。

本次修复：

- 第 6 步将图片保存到浏览器 IndexedDB，等事务提交后才记录缓存索引。缓存不可用时保留当前 File，后续可从原视频重建。
- 第 7 步先读取已完成图片的结果；需要继续处理的图片缺少 File/缓存时，按原决策范围重新生成该图。原视频也不可用时仍需用户重新选择素材。
- 图片分析使用独立子步骤，标识由决策、抽帧数、提示词的稳定哈希生成。重试沿用同一标识；父步骤只在整批完成后结束。
- 网页父步骤使用 `analyze-timeline-images.batch-v2`，兼容旧版本已经将 `analyze-timeline-images` 提前完成的运行。界面步骤 ID 保持原有含义，心跳以其前缀续租父子步骤。
- 网络读取失败、缺少最终流式结果、可重试的服务错误最多重试两次，等待 3/8 秒；取消立即终止等待。权限、余额、输入错误不会无限重试。
- 每张成功结果存入现有浏览器工作流数据库，按项目、运行、输入哈希和图片步骤隔离，24 小时过期。忽略过期或无效缓存；提示词变化不复用旧结果。结果缓存不保留原始模型响应 `raw_result`。
- 最终失败保留原始错误、图片序号和总数，提示继续时复用已保存的结果。空模型结果不会当作成功。浏览器存储失败会留下诊断，并提示刷新后可能需要重新分析。

生产后端 v2.1.59 已支持子步骤和父步骤心跳，此次不需要调整后端或模型配置。旧版本没有保存的图片分析结果无法事后补回；首次恢复旧任务可能需要重新分析。

验证覆盖独立子步骤、途中失败后续跑、请求标识稳定、重试上限、取消、空结果、提示词变化、旧父步骤兼容和缓存隔离/过期。另用真实 Chromium 验证图片字节和分析结果在页面刷新后可从 IndexedDB 恢复。测试不调用生产模型，不修改用户项目。

同时修正了既有页面规范检查的扫描范围，排除 `.test.tsx` / `.spec.tsx` 中用于测试的原生控件；产品页面仍受原检查约束。
